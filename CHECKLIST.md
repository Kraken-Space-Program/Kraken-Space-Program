# Kraken Space Program — Checklist

> If you cut a corner, write it here **before you close the PR**. Not later. Now.
> Future contributors will not remember it was intentional and will waste time wondering if it's a bug.
> If you fix a debt item, remove it from the table and note what you did in the commit message.

## Known Tech Debt

| # | Description | Where | Cut in Phase | Should be fixed by Phase |

| 6 | Propellant crossfeed is "same vessel, same `FuelGroup`", where fuel groups are assigned at assembly and change at decoupler boundaries. Real crossfeed flows through attach nodes with per-node rules. The simple version behaves correctly for stacks; it will be wrong for anything with radial tanks. | `src/part_modules/engine.rs`, `src/vessel/assembly.rs` | 1 | 2 |
| 28 | An engine draws each propellant in full and *then* scales its thrust by the worst shortfall, so whatever it already drew stays drawn — propellant is consumed for thrust that is never produced. Stock content hides it exactly: the tank holds 600 kg of RP-1 to 1400 kg of LOX and the engine asks for `{ RP1 = 0.3, LOX = 0.7 }`, so both run dry on the same tick and the loss is bounded by one tick. Any mismatch — a modder's tank, a different mixture, a part fuelled by hand — has the engine draining its abundant propellant at full rate while producing almost nothing. The fix is a two-pass draw: ask what is available, then take `demanded × fraction`. That needs an `available()` beside `draw()` on `ResourceContainer`, which does not exist yet. | `src/part_modules/engine.rs`, `src/part_modules/resource_container.rs` | 1 | 2 |
| 7 | A decoupler's `node` field is parsed but ignored — staging assumes every decoupler releases downward, which is true of stack decouplers and false of radial ones. | `src/vessel/staging.rs` | 1 | 2 |

They are there because that file is the single f64→f32 conversion point, which is a rule worth keeping, but they are simulation types and not rendering types. DESIGN.md's dependency rules said "zero dependencies on `rendering/`" and were quietly untrue for the whole of Phase 1. Either they move somewhere neutral or the rule stays as it now reads. | `src/rendering/render_sync.rs`, `src/physics/` | 1 | 3 |
| 29 | `Transform::from_translation(position.as_vec3())` casts a simulation position to f32 outside `render_sync.rs`, against the rule `rendering/mod.rs` states as absolute and `CONTRIBUTING.md` lists as enforced by reviewers. It is a no-op today — vessels only ever spawn on the pad with `WorldOrigin` at zero — and becomes a real precision error the moment anything is spawned far from the origin, which is Phase 2's save loading. Subtract the origin before the cast, the way `render_sync` does. Note for whoever picks this up: the other five `.as_vec3()` calls outside `render_sync` are forces, torques and joint anchors, which the rule does not cover and which must be left alone. | `src/vessel/assembly.rs` (`spawn_part`, `spawn_visual`) | 1 | 2 |
| 26 | Every engine on a vessel burns whenever the throttle is open. Nothing ties ignition to a stage number, so an upper stage's engine runs from the pad — on the test stack the Spark burns ~300 kg of its own propellant lifting the first stage, and total thrust reads 140 kN when only 120 kN of it is doing useful work. Found by the first ascent to space, where "stage when thrust reaches zero" never triggered because the upper engine was still running. A real fix wants a per-part stage assignment, which is the editor's job (#8). | `src/part_modules/engine.rs`, `src/vessel/staging.rs` | 1 | 4 |
| 24 | Engine gimbals and RCS thrusters still do not exist, so `reaction_wheel` is the only source of attitude authority. Real vessels steer mostly by gimballing the engine, which is also the only thing that works once reaction wheels saturate. | `src/part_modules/` | 1 | 2 |
| 25 | Reaction wheels never saturate, need no electricity and work in a vacuum forever. They are a torque source with no cost and no limit, which is exactly the thing KSP is most often criticised for. | `src/part_modules/reaction_wheel.rs` | 1 | 3 |
| 21 | Landing gear is a whole part at the bottom of the stack, not legs that attach radially to the sides of one. Radial attachment needs the editor (debt #8). ## Resolved

Kept briefly so reviewers can see what changed and why, then deleted.

| Was | Resolution |
|-----|------------|
| Attitude control was one global constant (debt #2) | `ReactionWheel` is a part module now, declared in Lua as `reaction_wheel { torque = 3.0 }`. A vessel's authority is the sum of what is bolted to it, each wheel applies its own share where the hardware actually is, and a vessel with no wheels has no attitude control at all — which is the point: stage away the probe core and the booster stops responding. `kraken.pod.probe` carries 3 kN·m, matching the constant it replaced so the test stack handles as it did. |
| Drag had no occlusion (debt #15) | `celestial::occlusion` projects every part onto the plane across the airflow and subtracts the overlap cast by anything upstream. A stack flying nose-first now presents one cross-section instead of five; flying broadside, every part counts, which is correct and is the case a "just take the biggest part" shortcut gets badly wrong. With shielding modelled, the stock `drag_coefficient` went back to a real 0.8 (blunt cylinder) from the 0.3 that existed only to cancel the overcounting. Parts also gained `drag_radius`, separate from the collision radius, because an open structure blocks far less air than it spans — the landing gear needs a 1.9 m footprint and would otherwise fall like a parachute. |
| No landing legs (debt #11) | `kraken.gear.lt2`, a `landing_leg`-shaped part at the base of the stack. It collides as a 1.9 m cylinder — a wide base of support is the whole mechanism — and draws as a hub with four splayed footpads on the rim, so what it visibly stands on is where the collider's bottom edge is. Verified with the scripted pilot: a hop that acquires lateral drift on the way up now lands intact and dead still, where the same profile previously toppled and destroyed the vessel. |
| Parts named `.glb` files that did not exist (debt #10) | Parts now declare a `shape` in Lua — `cylinder`, `engine`, `decoupler`, `nose_cone`, `landing_leg` — which is the authoritative geometry: the collider and the placeholder mesh are both built from it and cannot disagree. A `.glb` became what it should always have been, an optional *visual* override that changes nothing about behaviour. This also removed the guesswork from collision: the collider used to come from attach-node spacing and a table of stock diameters, so a part's physical size would have silently changed the day a real mesh arrived. The Spark's top attach node, which sat at the origin with a comment admitting the model did not exist, is now at the top of the engine body. |
| Structural failure not implemented (debt #1) | `joints::detect_joint_failures` reads the solver's constraint impulses each tick, converts them to axial and shear forces, and compares against the limits from Lua. Breaking requires the limit to be exceeded for three consecutive ticks — a rigid contact at 50 Hz stops a vessel inside one step, which is 217 kN through a 67 kN joint for a 1.8 m/s touchdown, so a single-tick test made every landing fatal. |
| No aerodynamic drag (debt #4) | `celestial::atmosphere` — exponential density, per-part `DragSurface`, force into `PendingForces`. A ballistic re-entry now peaks at 291 m/s at 4 km and *slows* to 274 m/s as the air thickens, instead of accelerating all the way down. |
| Engines always used sea-level Isp (debt #3) | Now interpolated on ambient pressure, which the atmosphere model made possible. |
| No crash detection (debt #5) | `physics/impact.rs` turns Rapier contacts into impact speeds, `vessel/damage.rs` breaks a vessel apart above `SAFE_IMPACT_SPEED_MS`. Two things had to be got right that are not obvious: the speed comes from the tick *before* the contact, because Rapier has already cancelled the velocity by the time the event is readable; and contacts between two parts of the same vessel are ignored, or the rocket destroys itself the first time it turns. |
| `eprintln!` instead of `tracing` | Enabled the `bevy_log` feature and replaced every call with `info!`/`debug!`/`warn!`. Note the original entry proposed adding a raw `tracing` dependency — that was the wrong fix; `bevy_log` is what installs the subscriber that makes `RUST_LOG` work. |
| `log_ball_position` spamming stderr every frame | Deleted along with the ball. The HUD replaced it. |
| `LocalOrigin` never updated | Now driven by `physics::krakensbane`, which keeps it equal to `WorldOrigin`. |
| Nothing carried `SimPosition` + `SyncRender` | Every part does. `physics::readback` derives `SimPosition` from Rapier each tick, and each part's visual entity follows it. |
| Physics interpolation not implemented | Implemented in `render_sync`, interpolating between the last two ticks by `Time<Fixed>::overstep_fraction`. Note this was a *second* bug in the same area: physics was also not actually running at 50 Hz — see EXECUTION.md's decision log. |
